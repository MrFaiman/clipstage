# Clipstage

**Your stream's best moments, straight to your editing team.**

A Kick-first, full-stack MVP: an OBS dock sends completed recordings or replay-buffer captures to private S3 storage; a shared workspace gives editors the original, a brief, and a saved VideoFlow timeline, and non-destructive review controls. MP4 exports download locally without replacing the source or uploading a new clip.

## Stack

- **Bun workspaces + TypeScript**
- **Next.js 16 / React 19**, Tailwind 4, custom-styled shadcn-style Radix components, Lucide, Zustand, SWR
- **NestJS 11**, Zod contracts, opaque cookie sessions
- **PostgreSQL 17 + Prisma 6**, private S3-compatible storage
- **Native OBS plugin:** C++17 + Qt 6



## Try the interface

Requires Bun 1.4.2+ and Node 22.12+ for framework/tooling compatibility.

```sh
bun install
bun run setup           # creates an ignored .env and a random encryption key
bun run db:generate
bun run dev:web
```

Open **[http://localhost:3000](http://localhost:3000)**. Demo mode is on by default: sample clips, local-only edits/uploads, no API or OAuth credentials required. The six illustrations and 12-second abstract preview are original demo assets, not real streamer footage. Reloading discards demo changes. Team invitations and device pairing are deliberately disabled in demo mode.

## Run the connected application



### 1. Start local services

Docker Compose runs PostgreSQL and **SeaweedFS's S3 API**. Only loopback ports are published; credentials in `infra/s3.local.json` are for local development only.

```sh
bun run infra:up
# Allow a few seconds for the services to start.
bun run db:deploy       # apply the committed initial migration
bun run storage:init   # create private local bucket + browser CORS
```

Defaults: PostgreSQL `localhost:5432`, S3 `localhost:9000`. Production can use AWS S3 directly; SeaweedFS is only the local emulator.

### 2. Register a Kick OAuth application

Create an application in Kick's developer settings. Set its callback URL to exactly:

```text
http://localhost:4000/v1/auth/kick/callback
```

Update `.env`:

```dotenv
NEXT_PUBLIC_DEMO_MODE=false
KICK_CLIENT_ID=your-client-id
KICK_CLIENT_SECRET=your-client-secret
```

Keep `TOKEN_ENCRYPTION_KEY` generated by `bun run setup`. OAuth requests only `user:read`; **no stream key is requested**. Both streamers and editors sign in with Kick in this first version. Login uses the official OAuth 2.1 authorization-code flow with PKCE. Real provider credentials are required to validate the complete Kick round trip.

### 3. Start both apps

```sh
bun run dev
```

- Web: **[http://localhost:3000](http://localhost:3000)**
- API: **[http://localhost:4000/v1](http://localhost:4000/v1)**
- Liveness: `GET http://localhost:4000/v1/health`

Sign in, invite an editor from **Your team**, then upload a source or pair OBS from **OBS integration**. An invitation matches a Kick email or username. Someone who already uses Clipstage joins immediately; otherwise they join the next time they sign in with that Kick account. No email is sent, and a pending invite expires in seven days. A user can join multiple workspaces and connect multiple Kick identities. Existing identities are never merged by email.

Use **localhost consistently**, not a mixture of localhost and 127.0.0.1. Restart Next after changing `NEXT_PUBLIC_`* variables. They are baked into production builds.

### 4. Build and pair OBS

See **[plugins/obs/README.md](plugins/obs/README.md)**. The plugin source builds against OBS 30+ and matching Qt 6. There are no prebuilt/signed installers yet.

The dock controls OBS's **normal recording output**. Start/stop it independently of the stream, or save a replay-buffer clip if you already record the full stream. Use H.264/AAC MP4 for reliable browser playback. Your source files are never deleted.

### VideoFlow editor

The full VideoJSON timeline is stored on the clip; the first video layer also updates the legacy source trim fields. Original media references are rebound to a fresh playback URL when reopened. Extra local files dropped into VideoFlow are temporary; remove them before saving or use durable media URLs. Export uses VideoFlow's built-in browser MP4 download and never uploads or replaces the source. Browser codec support and asset CORS apply.

Existing installations: run `bun run db:deploy` and `bun run db:generate` for the new nullable `Clip.project` JSON column.

`@videoflow/react-video-editor` uses a tiered license: free for individuals, eligible nonprofits, and for-profit organizations with up to three employees; larger commercial organizations need a company license. Check [VideoFlow's license](https://videoflow.dev/license) before deployment. Core and renderers are Apache 2.0.

## Commands

```sh
bun run check               # workspace/tooling TypeScript checks + unit tests
bun run build               # Nest/Bun bundle + Next production build
bun run test:integration    # real Nest + local Postgres/S3, isolated temporary fixtures
bunx playwright install chromium
bun run test:e2e            # desktop/mobile interactive demo tests
bun run test:live           # also exercise a real browser → API → S3 → editor flow
bun run format
bun run db:migrate          # create a migration after changing the Prisma schema
bun run infra:down          # stop services; preserve data volumes
```

Run integration/live tests **only against the local development services**. They create and remove their own database rows and S3 objects; they don't reset the database. Ports 3000 and 4400 must be free for browser/live tests. Don't run the browser suites concurrently.

Linux native compilation check:

```sh
docker build -f plugins/obs/Dockerfile.buildcheck plugins/obs
```

Actual OBS GUI capture and Windows/macOS builds are not covered by this compilation check.

## Before production

This is an MVP foundation, **not a production-hardened video platform**. Read **[the architecture and rollout checklist](docs/architecture.md)** and **[API contract](docs/api.md)**.

Important: the browser app and API must share a **hostname** because sessions are host-only cookies consumed by both Next's server loader and Nest. In production, terminate TLS at one origin and route `/v1/`* to Nest, everything else to Next. Set `WEB_ORIGIN` and `API_ORIGIN` to that same HTTPS origin. `API_INTERNAL_URL` may point from Next directly to the internal Nest service. Do not expose the database or local storage admin credentials.
